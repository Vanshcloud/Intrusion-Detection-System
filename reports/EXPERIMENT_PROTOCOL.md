# Experiment Protocol v1 — improved CIC-IDS2017

Generated by `scripts/render_reports.py` from `configs/experiment_protocol_v1.json`, `configs/feature_manifest_v1.json`, `configs/label_mapping_v1.json` and `reports/generated/m3_*` (all produced by `scripts/prepare.py`). Status: **frozen before any model training; changes require a new version with a reason**. No model has been trained under this protocol yet.

## 1. What this evaluation measures — and what it does not

**Measures:** how well a flow-feature classifier trained on the earlier part of each labelled traffic stratum (each attack episode and each day's benign traffic) recognises flows from the later part of the *same* stratum, in the *same* 2017 testbed, with the same attacker, victims and tools, and — separately — on test flows whose exact feature vector never occurs in training.

**Does not measure:** detection on independent networks, independent attack campaigns, unseen attack types, or real future traffic; deployment performance; robustness to adversaries. The split is built *within* (day, label) groups, i.e. it uses the labels retrospectively to decide where each group is cut — a deployed detector never knows where an attack episode starts or ends. Training data therefore includes traffic that is later in wall-clock time than some test traffic of the same day (§6). Results must never be described as real-world or deployment performance.

## 6. Splits

**Primary (`chrono`).** Strata: (day, original Label). Order: t_start, source_file, source_row. Sizes: per stratum: test = round(0.3 n), val = round(0.2 * (n - test)), each >= 1; rest train (~56/14/30). Purge: drop train rows with t_end >= first val t_start of the stratum; drop val rows with t_end >= first test t_start. Test rows are never removed.

**Why chronological:** each attack exists as a single episode on a single day (DATA_AUDIT §5), so a supervised benchmark has to train and test inside episodes; ordering by time keeps every test flow later than its stratum's training flows, and purging removes flows whose time interval (up to 120 s) crosses a boundary. Chronology alone does not reduce exact-duplicate overlap (LEAKAGE_AUDIT §5), hence §7.

**Validation partition:** the last ~20 % (before test) of each stratum's pre-test part; chronologically after train and before test in every stratum. A single global time cut per day was not used: attacks occupy short windows, so a day-level cut would put whole attack types only in train or only in test. Compromises (measured): rare classes get 2–9 validation rows (Heartbleed 2, SQL Injection 2, XSS 2, Infiltration 5, Brute Force 9) — useless for per-class tuning; thresholds are therefore selected on the binary task only. Purging shrinks some validation sets strongly because those attacks keep long connections open (see table).

## 7. Novel-vector test subset

- Definition: test row whose exact ordered feature vector (for that feature set) does not occur in the training partition of the same protocol/variant; floats canonicalised (-0.0 -> 0.0, single NaN); 128-bit hash match confirmed by exact per-column comparison.
- Reference set: train partition only (models are fitted on train only in v1).
- Near-duplicates: same equality on non-timing features only (reported, not used as a subset).
- Recomputed for every (protocol, label variant, feature set); stored as boolean columns in `data/processed/novel_test_v1.parquet`.
- It is **not** unseen-attack detection and **not** independent-network generalisation: every novel test flow still comes from an attack type, host and tool present in training.

## 8. Preprocessing and model selection

- src/ids/pipeline.py: fitted on train rows only (constant-column filter; one-hot + scaling for linear models).
- hyper-parameters and thresholds chosen on val only; test untouched until final evaluation.
- Models are fitted on `train` only in v1 (not re-fitted on train+val), so the novel-vector reference set is exactly the fitted data.

## 9. Metrics (defined in `src/ids/metrics.py`)

- Positive class / score: attack (y_binary = 1); score = model probability of attack.
- Threshold-free: PR-AUC (average precision) - primary threshold-free summary, prevalence-dependent; ROC-AUC - secondary; can look high while false alarms are operationally large.
- Operating points: threshold = highest validation recall with validation FPR <= budget, budgets [0.001, 0.01]. Two false-alarm budgets are fixed now, before any result exists, because a detector's usefulness depends on false alarms at realistic volumes (at ~478k benign test flows, 0.1 % ≈ 478 false alerts).
- At each threshold: precision, recall, F1, FPR, false-positive count, confusion matrix, per-original-label detection / alert rate with support.
- Multiclass: per-class precision, recall, F1, support; macro-F1 over classes present in test.
- Undefined values: reported as null, never replaced by 0/1.
- Support below 30: flagged unstable.
- Evaluation sets: full test, novel-vector test.
- No single metric is the optimisation target: PR-AUC summarises the attack class but hides the false-alarm volume; the FPR-budgeted operating points make that trade-off explicit.

## 11. Versioning rule

This protocol is frozen before training. Any change (cleaning, features, split, metrics, thresholds) creates `experiment_protocol_v2.json` with a written reason; v1 artifacts are not overwritten. The split must not be changed after test results have been seen.
