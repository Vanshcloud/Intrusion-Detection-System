# Leakage Audit — improved CIC-IDS2017 (Milestone 2)

Generated by `scripts/render_reports.py` from `reports/generated/*`. Exploratory screening only; no model has been trained or evaluated. Each section separates **Observed evidence** from **Interpretation / possible risk**.

Screening method: for each column, a one-feature classifier fitted on a random half and scored (balanced accuracy, 0.5 = chance) on the other half — a depth-3 decision tree for numeric columns, a value→majority-label lookup for identifier columns. Binary target: attack vs benign with Attempted → Benign. Per-attack: that label vs a fixed 50k sample of same-day benign flows. Mutual information on a 50k/50k stratified sample. Random halves make these scores optimistic by construction (duplicates), which is acceptable for *flagging*.

## 2. Direct target leakage

**Observed evidence.** `Attempted Category` is non-(−1) on exactly the `- Attempted` labels (consistency check: True). No other column is a copy of the label.

**Interpretation / risk.** Including `Attempted Category` would leak the label policy itself. Excluded by `model_features()` and asserted in `tests/test_basics.py` and `tests/test_dataset.py`.

## 4. Temporal leakage

**Observed evidence.** Every attack label lives in one contiguous window on one day (DATA_AUDIT §5); files are not time-ordered; flows last up to 120 s, so a flow starting before a split point can overlap flows after it. Repeated identical vectors in scans recur within ≤ 1 s (DATA_AUDIT §7).

**Interpretation / risk.** A random split places each test flow next to near-identical training flows from the same second. Time itself is a near-perfect attack indicator within a day, so no time-derived feature may be used.

**Interpretation / risk.**
- The chronological within-label split does **not** reduce exact-duplicate overlap relative to a random split: the overlap comes almost entirely from Portscan / Infiltration–Portscan, whose identical probe vectors recur across the whole episode, not only near the boundary. It does move test flows away in time (median distance to the nearest same-label training flow rises from ~0 s to tens–hundreds of seconds).
- DoS/DDoS have no exact duplicates, but most test rows match a training row on every non-timing feature under *any* within-episode split → the test set measures recognition of the same tool run (scenario memorisation), which no split inside a single episode can remove.
- A 120 s test-side embargo discards a large share of test rows of the short DoS/DDoS episodes while leaving the duplicate overlap nearly unchanged; 600 s removes whole test portions. Purging training flows costs far less and removes the interval overlap.
- Burst holdout (B) degenerates to A for single-burst labels and produces extreme partitions where it applies (see Infiltration–Portscan, SSH-Patator rows). Episode holdout (C) is infeasible: most labels have one episode.

## 6. Preprocessing leakage risks

**Observed evidence.** Constant columns differ by day (DATA_AUDIT §8); infinite rates exist; class priors differ strongly by day.

**Interpretation / risk.** Any scaler, imputer, constant-column filter, feature selector or resampler must be fitted on training rows only (sklearn `Pipeline`). Deduplication decisions must use training rows only. Thresholds must be chosen on a validation slice carved chronologically from the training portion.

## 9. Proposed mitigations

1. Exclude `Src IP`, `Dst IP`, `Src Port`, `Flow ID`, `id`, `Timestamp`, provenance columns and `Attempted Category` from features (enforced in code + tests).
2. `Dst Port`, TCP-stack fields and header-length fields: with/without ablations.
3. Primary split: chronological within each (day, label) stratum with training-side purging (see recommendation below).
4. Report metrics on the full test set and on the *novel-vector* test subset (feature vector never seen in training).
5. Random stratified split only as a labelled optimistic baseline; held-out-attack experiment reported separately.
6. All preprocessing inside a train-fitted pipeline; tests assert fitted transformers only see training indices.
7. Never claim the dataset or the evaluation is leakage-free: scenario memorisation remains (§5).

## 10. Validation design — evaluation of candidates and recommendation

(`attacks` in the split tables = all non-benign raw labels, including `- Attempted`.)

| Candidate | Evidence from this data | Verdict |
|---|---|---|
| A. Chronological 70/30 within each (day, label) | test overlap 0.439 exact / 0.886 non-timing vs random 0.442 / 0.893; moves test later in time; every label present in train | Usable as the base, **not sufficient alone** |
| A + test-side embargo 120 s / 600 s | attack test rows 89,290 / 26,579 of 155,236; overlap barely changes | Rejected: large test loss, little benefit |
| A + training-side purge | 3,702 training rows removed; no test loss; removes flow-interval overlap across the cut | **Adopt** |
| B. Burst (grouped temporal) holdout | most labels have one burst; where several exist the partition is extreme | Rejected as primary |
| C. Episode holdout | needs ≥ 2 independent episodes per label; not available | Infeasible |
| D. Random stratified | median 0 s to nearest same-label train flow; exact/non-timing overlap about equal to A | Optimistic baseline only |
| E. Held-out attack family | only way to probe beyond the scripted run | Separate experiment, not the benchmark |


**Recommended primary design (proposal for review):** chronological 70/30 split by flow start within every (day, raw label) stratum — including each day's benign traffic and the `- Attempted` flows — with training rows purged when their flow interval reaches past the stratum's cut; ties ordered by (`ts`, `source_file`, `source_row`); hyper-parameters tuned on a chronological slice of the training part only; metrics reported on (a) the full test set and (b) the *novel-vector* test subset; classes with < 30 test rows reported with counts and flagged.

**Why:** each attack exists in a single episode on a single day, so a supervised benchmark must train and test inside episodes; chronology keeps test data strictly later; purging removes interval overlap at negligible cost; the novel-vector subset handles the duplicate leakage that chronology cannot. **Known limitation:** train and test share tool, attacker, victim and run — non-timing overlap stays high — so results estimate within-scenario forward generalisation and remain optimistic. The random split (D) quantifies that optimism; E is reported separately.

## 11. Milestone 3 — implemented safeguards and measured residual risk

**Observed evidence (implemented split, `configs/experiment_protocol_v1.json`).**

- Purging removed 6,722 train/val rows; no test row changed.
- Exact overlap of attack test rows with training: chrono 0.443, random 0.445; near (non-timing) overlap 0.873 vs 0.882. With `Dst Port` added the exact overlap is 0.223 — novelty depends on the feature set, so it is recomputed per set.
- Friday: 220,170 of 305,662 training rows start after the first Friday test flow.

**Interpretation / possible risk.** The implemented design removes interval overlap and makes duplicate overlap measurable, but it does not remove scenario memorisation (same tools, hosts and run in train and test) and it uses label-defined strata. The dataset and this evaluation are **not** leakage-free; results are within-scenario estimates. Details: `reports/EXPERIMENT_PROTOCOL.md`.
